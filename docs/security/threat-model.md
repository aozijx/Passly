# 威胁模型

## 范围

| 威胁          | 目标        | 主要控制                             |
|-------------|-----------|----------------------------------|
| 设备丢失或离线文件拷贝 | 数据静态机密性   | SQLCipher、字段加密、Keystore、Argon2id |
| 恶意备份获取者     | 备份机密性和完整性 | 独立密码、Argon2id、AES-GCM、格式校验       |
| 应用层越权与日志泄露  | 最小化明文暴露   | 包边界、Repository 解密边界、日志禁令         |
| 数据库/备份篡改    | 完整性       | AEAD tag、严格解析、事务回滚               |
| 生物识别取消或失败   | 会话状态一致性   | 单一事件通道、失败不解锁、Scope 不被取消          |
| 剪贴板遗留       | 二次泄露      | 定时清理与可控 Toast                    |

## 非目标与残余风险

已 Root 且能持续读取进程内存的攻击者、已攻破可信执行环境的攻击者、用户主动复制到不可信应用后的数据流转，不在应用可完全消除的边界内。内存覆盖是降低窗口的尽力措施，不是
JVM 上的可验证擦除保证。

## 风险优先级

优先处理会导致永久数据丢失、错误解锁、明文持久化、认证绕过和备份不可恢复的问题；其次处理元数据暴露、短暂内存副本和通知隐私。安全设计变化必须能对应到威胁、测试和
ADR，避免只增加复杂度而没有可验证收益。

## 审查清单

- 数据库打开失败是否保留原文件？
- 所有解锁方式是否验证同一 DEK verification tag？
- 认证取消是否只产生一次消息并保持会话 Locked？
- 锁定后数据库、DEK 和派生密钥是否全部失效？
- 备份头、密文和 ZIP 是否严格校验并限制大小/路径？
- UI、日志、崩溃报告是否可能保留密码或恢复码？
