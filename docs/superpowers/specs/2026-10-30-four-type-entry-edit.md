# 四种凭据类型的完整表单编辑

## 状态

已批准实施，范围限定为 Login、OTP、Bank Card、Wi-Fi 四种现有创建类型。

## 目标

从条目详情进入与创建共用的类型表单，修改已有条目。其他类型继续使用详情页现有的单逻辑字段编辑，不新增通用表单策略、插件或适配器注册架构。

## 约束

- 编辑路由只携带 `entryId`；类型必须从仓库读取，不信任路由传入类型。
- 类型表单状态仅保存在 ViewModel 内存中，不写入导航参数或 SavedState。
- 加载时读取条目和高敏字段存在性。对该类型所有已存在的高敏字段使用一个精确范围的 `REVEAL` 授权；拒绝、取消、会话变化、仓库返回缺字段时都不打开表单。
- 缺失的高敏字段显示为空，可由表单按现有创建规则设置；已存在字段必须先成功揭示再允许进入表单，避免空值覆盖。
- 锁定、认证对象更换、路由销毁或条目切换时取消加载/保存并清空表单。迟到结果不得发布到新会话。
- 复用四个现有表单、校验及 `toEntryDraft()` 映射。Draft 仍表示完整表单输入；Domain 将其应用到最新条目时只替换表单拥有的字段，并保留身份、版本、时间戳、收藏、图标、过期时间、自定义字段及其他非表单状态。
- 使用现有完整条目校验和带预期版本写入；冲突重试必须重新读取最新条目并重放同一表单输入，且不能丢失刚揭示的高敏值。
- 更新成功返回详情页；失败保留可修正的表单输入；不记录凭据内容。

## 结构

1. 在 Domain 增加纯函数，将四种类型的 `EntryDraft` 应用到同类型现有 `Entry`，验证输入类型/字段和最终凭据，保留表单未拥有的状态。
2. 增加编辑加载用例：验证完整会话，读取条目及敏感字段存在性，为所有存在的高敏字段请求单次授权读取，确认返回集合完整并记录 VIEW 使用，产出显式的成功/未找到/不支持/拒绝或不完整读取结果。
3. 增加完整表单更新用例或扩展现有更新用例：加载最新条目、应用 Domain 变更、比较 Profile/Secret 并使用现有乐观版本更新及一次冲突重试。
4. 四个现有 ViewModel 支持 Add 与 Edit 两种模式；分别管理表单加载和保存状态，不把创建用的 `EditorSaveSession` 直接当作更新会话。
5. 详情仅对四种类型展示完整编辑入口；四种编辑路由只接受 `entryId`，加载后类型不匹配则安全退出并显示通用失败反馈。
6. 更新功能文档，列明认证读取、类型范围、编辑用例和当前验证边界。

## 不做

- 不为其他 EntryType 增加完整编辑。
- 不增加 `EntryEditorRegistry`、`EntryFormAdapter`、每类型插件或第二份支持类型清单。
- 不改写创建流程、外部存储格式、数据库 schema 或认证策略。

## 验收

- 高敏字段存在时授权拒绝、取消、部分读取、锁定或认证对象切换，都不会显示/保存空值表单。
- 四种类型的合法表单可回填、修改并持久化；非法值不会写入。
- 收藏、图标、过期时间、自定义字段以及用户未通过表单编辑的条目数据在更新后保留。
- 并发版本冲突时重新读取并安全重放；无变更为成功空操作。
- 非四种类型没有完整表单编辑入口，直接进入不支持路由也不能回退到其他表单。
- 相关 Domain、App 测试、架构校验、编译与 `git diff --check` 通过；设备验收单独报告。
