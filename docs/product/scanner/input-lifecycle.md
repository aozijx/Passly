# 扫描输入与生命周期

状态：相机/图片主链路已实现；`Work.HostPaused` 与显式 `Work.Stopped` 已区分。剩余 Route、解码器、候选几何和设备验收见[Scanner 行为与设备计划](../../project/work/plans/2026-11-06-scanner-entry-and-framing.md)；Camera Host 资源生命周期验收由[并发计划 Task 5](../../project/work/plans/2026-11-06-app-architecture-concurrency-todo.md#task-5)跟踪。

相机帧和相册图片都产生原始扫码文本，但输入资源及取消合同不同。`ScannerCameraHost` 持有 CameraX/ML Kit 与 `ImageProxy`；`ScannerViewModel` 持有扫描任务 owner、扫描 UI state、单个带消费确认的反馈状态及剪贴板写入；`ScannerRoute` 持有相册选择、生命周期 effect 与 owner 提供的结果计划。扫码层不解析内容类型，调用方在自己的业务入口转换。

## 相机输入

相机授权由 `ScannerCameraHost` 请求；它只管理权限、Compose 生命周期和共享资源。`bindScannerCamera()` 创建 Preview 与 ImageAnalysis，`ScannerCameraSession.bind()` 等待 `previewView.viewPort`、布局尺寸和未销毁状态就绪后，再将 use case 放入同一 `UseCaseGroup`。`ScannerCameraSession.stop()` 只解绑本 session 持有的 Preview 与 ImageAnalysis，不调用会影响同一 `ProcessCameraProvider` 其他 use case 的全局 `unbindAll()`。`createScannerImageAnalysis()` 专管帧处理：用当前 `ImageProxy.cropRect`、旋转角度、预览尺寸和共享取景框创建 `ScannerRecognitionRegion`；坐标暂不可用时关闭并跳过该帧，不启动 ML Kit。有效时才构造 `InputImage`；回调先筛选有 `rawValue` 且实际 `cornerPoints` 四角都位于区域内的候选，无 corner points 时才检查 `boundingBox` 四角。`addOnCompleteListener` 关闭当前 `ImageProxy`。退出 effect 时设置原子 `disposed` 标志并由 Session 停止相机；组件释放时也关闭 executor 和 ML Kit scanner。

`ScannerRoute` 从 `BoxWithConstraints` 读取可用尺寸，由 `ScannerViewfinderFrame.fitContainer()` 统一计算并转换视框几何。Route 将相同的 frame 交给相机 Host 和 `ScannerScreen`；Screen 只接收 `ScannerScreenUiState`、独立投影的 `ScannerCameraState`、取景框和用户操作回调。相机输入位于 `presentation.camera`，Route 和 UI 共用的取景框几何位于 `presentation.viewfinder`，图片输入位于 `presentation.image`；状态契约、reducer 与 Screen 状态映射位于 `presentation.state`；Screen 操作与输入事件位于 `presentation.action`；结果计划和展示策略位于 `presentation.integration`，确认会话及其阶段位于 `presentation.integration` / `presentation.result`。Route、ViewModel 和 Compose UI 分别位于 `presentation.route`、`presentation.viewmodel` 和 `presentation.ui`，Route 负责连接屏幕状态、平台 API/生命周期、调用方结果计划与展示 UI；`ScannerScreen` 只收状态和回调，不依赖 ViewModel 或导航实现。`ScannerUiState` 直接用 sealed 状态表达扫描、图片处理中、结果展示和停止；只在扫描/结果状态上携带单个可消费反馈，不再用外层 phase 包装；`ScannerScreenUiState` 用 sealed 状态表达隐藏、扫描、图片处理中、停止和结果展示；携带扫码值、调用方展示策略及结果操作状态的 `ShowingResult` 使用 data class。Route 从 `ScannerUiState` 与 overlay 单独映射 `ScannerCameraState`，并同时传给相机 Host 和取景框；结果卡片和顶部栏直接消费 `ScannerResultActionState`，不再通过布尔状态参数拼装界面。`ScannerOverlay` 通过 `AnimatedVisibility` 控制 Route 的显示；`ScannerRoute(visible)` 在可见周期启停扫描，`ScannerResultPhase` 表达确认会话阶段并只映射一次为 `ScannerResultActionState`，Route 的动作门控与 Screen 按钮展示共用该投影。`ScannerScreenAction` 只表示屏幕上的用户操作；相机权限、识别结果和相机错误由 Host 回调直接进入 Route/ViewModel，不混入 UI state。`ScannerResultSession` 由 Route 按可见周期持有，不随扫码内容状态变化重建；确认或关闭期间锁住结果操作，普通异常会回传无详情的失败结果并保留卡片重试，关闭后的迟到失败回执忽略，取消和 fatal `Error` 仍传播。`ScannerRecognitionRegion.create()` 使用 CameraX `ImageProxyTransformFactory` 和 PreviewView 输出变换构造坐标转换；识别时将 ML Kit 返回的旋转后条码角点转换到 PreviewView 坐标，再与同一份取景框几何比较。候选的实际四角必须全部落在取景区域内，防止只因中心进入框内就接收实际越界的码。

只有区域有效且条码四角完整位于取景区域内的候选才会触发扫描完成；没有 `rawValue` 的候选会在映射之前排除，避免挡住后续有效候选。

`ScannerScreen` 以 Material 3 `CenterAlignedTopAppBar` 显示返回箭头、标题和相册操作；格式提示及中英文资源已删除。结果 `AnimatedContent` 使用 `.using(null)` 禁用父容器的尺寸变换，卡片保持底部锚定并只做淡入和上移动画。Vault、OTP 与 Wi-Fi 编辑器通过 `AnimatedScannerOverlay` 展示 Scanner。Route 按可见周期创建结果会话，并由一个 `DisposableEffect` 在可见时派发 `StartScanning`、离开可见周期时派发 `StopScanning`；隐藏时由可见状态锁住操作，上一会话在离开组合时关闭。这是因为 Route 的 Hilt ViewModel 归宿主导航项所有，Route 内容可能在退出动画反转时复用，而不是重新创建。关闭动作先关闭结果会话，再通知父层开始退出动画。

`ScannerRoute` 将检测回调映射为 `ScannerUiAction.BarcodeDetected(action.rawValue)`。`ScannerViewModel.onAction(action)` 只在 `uiState.value is ScannerUiState.Scanning` 时接收帧，并调用 `completeScan(raw)`；该函数拒绝空白值，替换当前 `Work.Active` owner、取消旧 owner、提交 `ScanCompleted(ScannerResult(raw))` 并把扫码成功反馈写入当前 UI state。之后的相机帧不覆盖已展示结果；Domain 解析和调用方处理不在此 ViewModel 内执行。

## 相册图片输入

`ScannerRoute` 通过 `rememberImagePicker { uri, _ -> ... }` 将平台 URI 包装为 `ImageRef(uri.toString())`，并派发 `ScannerUiAction.DecodeImage(image)`。选择照片前先派发 `StartScanning`。若 picker 期间宿主停止，`ScannerViewModel.pauseForHost()` 把 owner 设为 `Work.HostPaused` 并让 UI reducer 进入 `Stopped`；图片结果到达时，`decodeImage(image)` 允许从 `HostPaused` 接管新 owner、恢复扫描状态并开始处理。显式 `StopScanning` 则设为 `Work.Stopped`，同一 `DecodeImage(image)` 会被拒绝；销毁后也拒绝输入。接管后在新 owner scope 中调用注入的 `decode(image)`。

默认解码器 `BarcodeImageDecoder.decode(ref)` 以 `withContext(Dispatchers.IO)` 调用 `InputImage.fromFilePath(context, ref.value.toUri())`，之后通过 `suspendCancellableCoroutine` 创建 ML Kit client 并调用 `scanner.process(image)`。完成 listener 先关闭 client；若 continuation 已取消就丢弃结果，否则把首个非空值变为 `Decoded(rawValue)`，无值返回 `NoBarcode`，Task 失败返回 `Failed(error)`。回到 ViewModel 后先执行 `currentCoroutineContext().ensureActive()` 并比较 `work === owner`，再把文本交给 `completeScan(rawValue)` 或把图片失败反馈加入 UI state；这样旧图片的迟到回调不能更新新任务。

`BarcodeImageDecoder` 在协程取消时通过 `invokeOnCancellation` 关闭 ML Kit client；完成 listener 与注册异常路径共享原子 close guard，确保 client 最多关闭一次。注册时单独传播 `CancellationException`，普通异常映射为 `Failed`，fatal `Error` 清理后继续传播。完成 listener 在构造结果前检查 continuation 是否仍 active，避免取消后的迟到回调读取或发布识别文本。目前没有可注入的 ML Kit client seam，client/Task/listener 行为测试缺口由[Scanner 行为与设备计划](../../project/work/plans/2026-11-06-scanner-entry-and-framing.md)跟踪。

## 生命周期与敏感状态

`collectScannerRouteFeedback()` 在宿主 `STARTED` 时派发 `HostStarted`，消费单个 `uiState.feedback` 并回传 `FeedbackConsumed(id)`；离开该状态派发 `HostStopped` 并清除待处理反馈。`ScannerViewModel.pauseForHost()` 轮换 owner：显示结果可保留，纯扫描和图片处理中状态转 `Stopped` 并记录为 `Work.HostPaused`；宿主恢复后重新开始扫描。若相册结果在宿主仍暂停时到达，`DecodeImage` 可以从 `Work.HostPaused` 接管为新 owner。显式 `StopScanning` 则记录为 `Work.Stopped`，迟到的照片结果和 `HostStarted` 都不能重建 owner；`onCleared()` 设为 `Work.Destroyed`，拒绝所有后续输入。

`ScannerViewModelTest` 分别覆盖显式停止、销毁后的迟到输入拒绝，以及宿主暂停期间 picker 结果接管 owner；HostStarted 只恢复 `Work.HostPaused`。Route/Activity Result、显式关闭、overlay 快速重开、owner callback 交错和候选几何边界尚无组合回归，具体范围见[Scanner 行为与设备计划](../../project/work/plans/2026-11-06-scanner-entry-and-framing.md)。复制文本同样在当前 owner scope 中运行，传给 `SensitiveClipboardWriter.writeSensitiveIf(text) { work === owner }` 的资格闭包会在平台写入前再次核对 owner。

复制成功、图片识别失败和扫码成功震动由 `ScannerViewModel` 作为带递增 ID 的单个 `feedback` 存入 sealed UI state；Route 仅在 `STARTED` 时执行平台反馈并确认消费，宿主停止时清除未消费项，避免后台重放。反馈只含类型和 ID，不含扫码文本；普通异常详情不进入 Toast。`rememberImagePicker` 的 Activity Result callback 派发 `DecodeImage(ImageRef(uri.toString()))`；`collectScannerRouteFeedback()` 在生命周期进入 `STARTED` 时派发 `HostStarted`。源码没有建立这两个回调的先后屏障，不能假设照片结果一定在恢复 effect 之后到达。ViewModel 已允许 `HostPaused` 接管有效图片结果，并拒绝显式 `Stopped`/`Destroyed` 后的输入；该回调与关闭/重开交错由[Scanner 行为与设备计划](../../project/work/plans/2026-11-06-scanner-entry-and-framing.md)跟踪。CameraHost 内的原始回调不直接写库或持久化扫描内容。

任务 owner、迟到图片结果和宿主暂停行为由 [`ScannerViewModelTest`](../../../app/src/test/java/com/aozijx/passly/feature/scanner/presentation/viewmodel/ScannerViewModelTest.kt) 覆盖；Route 生命周期与反馈消费由 [`ScannerRouteFeedbackTest`](../../../app/src/test/java/com/aozijx/passly/feature/scanner/presentation/route/ScannerRouteFeedbackTest.kt) 覆盖。它们使用注入的 decode lambda 验证 ViewModel 编排，不调用真正的 ML Kit client；`BarcodeImageDecoder` client 清理与 Task/listener 边界暂无专用自动化测试，待办见[Scanner 行为与设备计划](../../project/work/plans/2026-11-06-scanner-entry-and-framing.md)。

相机坐标矩阵按 [CameraX 输出变换说明](https://developer.android.com/media/camera/camerax/transform-output)从 crop rect 和 rotation 映射；共享 [`ViewPort`](https://developer.android.com/reference/androidx/camera/view/PreviewView#getViewPort()) 使 Preview 与 ImageAnalysis 使用同一可视裁剪。ML Kit 将条码坐标定义在输入图像中，并提供 [`cornerPoints`](https://developers.google.com/android/reference/com/google/mlkit/vision/barcode/common/Barcode#getCornerPoints())；当前规则要求四个角都通过 [`RectF.contains(x, y)`](https://developer.android.com/reference/android/graphics/RectF#contains(float,%20float))，因此右/下边界不包含。旋转方向和取景裁剪的设备验收见[Scanner 行为与设备计划](../../project/work/plans/2026-11-06-scanner-entry-and-framing.md)。
